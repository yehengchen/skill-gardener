# 试用、反馈与养护

## 试用

选一个小而真实的任务，记录输入摘要、验收标准、平台与技能版本。不要把私人原始文件、聊天或凭据复制进历史，只保存必要摘要和产物位置。

1. `trial-start <skill-id> --task "脱敏摘要" --criterion "成功标准" --platform Codex` 创建 pending 记录。
2. 用真实技能执行，使用单独输出目录保护原件。“隔离目录”不是安全沙箱；权限和依赖按实际任务判断。
3. 检查结果。成功时 `trial-finish <trial-id> --outcome success --evidence <真实产物路径或结果链接> --note "检查结果"`；失败/阻塞如实记为 `failed/blocked`。
4. 用户明确评分时加 `--rating 1..5`，也可稍后 `feedback <skill-id> --rating ... --note ...`。沉默不代表满意，安装完成不代表任务成功。
5. 用户说“留着常用”就 `favorite <skill-id> --reason "用户要求保存常用"`，无需再次确认。

已完成的正常任务可用 `record-use`，需提供实际结果证据。重复结束同一次试用会报错，避免重复统计。不同平台与版本分别保留。

## 状态

- active：通过审查的工作库，参与默认推荐。
- candidate：新招募或同类待比较的候选区；默认不推荐，等待阅读、比较与试用。
- archived：从工作库或候选区出库，默认不推荐；资料、收藏标记与历史仍保留。恢复时回到归档前的区域。
- favorite：独立标记，表示用户常用偏好，不代表验证等级。
- installed：索引有可读本地入口，不代表宿主已启用或成功运行。

## 整理

`maintain` 生成清单，区分非收藏超过默认 90 天未用、来源证据超过默认 30 天未复核、上游归档/废弃/不可用、最近连续失败至少 3 次、同名不同来源，以及候选区超过默认 30 天仍未试用。新入库不足 90 天不算闲置；blocked 不算失败。

收藏项保留并提示问题。未知维护日期不是自动出库理由，源归档不证明现有版本失效。

用户要求自动整理时，在授权范围用 `maintain --archive-unused --archive-stale-candidates --reason "用户要求整理闲置与候选项"`，仅归档长期未用的非收藏 active 条目和过期未试用的非收藏 candidate 条目。针对失效项先核验影响，再 `archive <id> --reason ...`；直接 archive 可处理用户明确点名的收藏项。

`restore <id> --reason ...` 恢复；重新扫描不恢复归档项。`history` 可解释何时、为何改变了库。不提供物理卸载或永久删除命令。

用户明确要求周期养护且有调度能力时，用宿主调度工具保存真实任务，带上技能与个人库绝对路径。只在实质变化或需处理时通知；本脚本不提供后台服务。
