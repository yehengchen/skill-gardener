# 洞察与探索

这些能力让 Skill 库像一个持续调整的小团队，而不是越堆越多的收藏夹。所有结论只使用本地索引和个人试用证据，不上传记录。

## 技能体检

运行 `doctor` 查看工作库、候选区、归档区、收藏、本地可读项、分类覆盖、用户偏好缺口、同类重叠和维护清单。它给出下一步队列，但不自动招募、晋级或归档。

“分类拥挤”只说明一个类别的 active 数量较多；“同类重叠”来自词汇与分类近似。两者都是阅读实际 Skill 和比较结果的入口，不能直接证明同质化。

用户可直接问：“给我的 Skill 库做一次体检，告诉我最值得处理的三件事。”

## Skill 履历卡

`passport <id或名称>` 将发布者描述、来源、安装状态、维护状态、依赖、输出、个人成功/失败和试用证据放在一张卡中。`verified_strengths` 只能来自成功的个人试用，不能把宣传描述写成已验证优势。

适合回答：“这个 Skill 为什么还留在库里？”“它真正帮我做成过什么？”“有什么风险或证据缺口？”

## 同类擂台

`duel <skill-a> <skill-b> [...]` 用同一视角比较状态、依赖、输出、费用、离线能力、成功/失败和评分。当一个 Skill 的成功证据明确更多时可以显示 `evidence_leader`，但这不表示它普遍更好。

证据不足或并列时，用同一输入、同一验收标准分别建立试用，再比较结果。适合处理工作库里功能重叠、候选是否值得替换已有项的问题。

## 探索位

`explore "当前任务"` 从 active 中挑一个与任务相关、但很少或从未有个人使用证据的 Skill。它解决长期只推荐熟悉工具造成的偏好锁定。

探索位必须满足当前硬条件，只提供一个，不降低主推荐的确定性。用户可以选择试用或忽略；不能因为被展示就增加使用次数、收藏或晋级。若没有相关项，如实返回空结果。

## 可以继续发展的方向

- 任务组合图：根据真实输入/输出串联多个 Skill，并检查交接缺口。
- 版本漂移提醒：同一 Skill 更新后提示重新试用，而不是沿用旧版本成绩。
- 便携偏好模板：只导出用户主动选择的非敏感偏好，方便多设备初始化。

这三项需要更可靠的输入/输出结构、版本迁移规则或用户明确的同步范围，暂不在当前版本自动执行。
